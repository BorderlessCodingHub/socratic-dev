# socratic.dev — Engineering Analysis

**Date:** 2026-11-09 · **Scope:** `main` @ `cafbcbd` (316 commits, last change 2026-08-29) · **Benchmarks:** Career Forge v2 (`career-forge-v2` @ `9e91e22`), Hone (`ANALYSIS-2026-11-06`)

socratic.dev is a well-built product. Its authentication is sound: it bridges
to the Borderless platform login, with no unsigned-token shortcut like the one
Hone had. It already has CI, Sentry, an AI cost ledger and atomic credit RPCs.
The weak spots are **data integrity** and **delivery**:

- Row Level Security (RLS) still lets users write their own `sessions` rows,
  which feed the ranking.
- Two AI routes write to sessions without checking who owns them, which
  exposes public replay pages to tampering.
- The client sends the prompt context, so the hint economy can be bypassed.
- The repo has had no activity since August and its docs describe a deploy
  that is not the real one.

| Layer | Tech | Notes |
|---|---|---|

| AI | `@anthropic-ai/sdk` direct: `claude-sonnet-5` (adaptive thinking + effort), `claude-haiku-4-5`; prompt caching; text streaming | `ai_usage` ledger per call (route, user, session, tokens, latency) |

| Design track | `@xyflow/react` + `dagre` graph canvas, vision review on submit | |
| Payments | Stripe Checkout (hint packs), webhook with idempotent `hint_purchases` | |
| Observability | Sentry (full SDK in the browser, fetch-based "lite" reporter on the server), PostHog via `/ingest` rewrite | |

### Strengths (keep these)

- **Auth bridge is the right design.** Platform credentials are checked server-side and the Supabase user has no password. This is what Hone had to be rebuilt to reach.
- **Credits and points are server-controlled.** `profiles` user-update policy was dropped (migration 010). `consume_hints`, `add_bonus_hints`, `award_session_points` and `join_and_add_league_points` are atomic and service-role only. Points farming was already patched once (021).
- **Payments done carefully.** Redirect origin pinned by env (not by the `Origin` header), safe relative path, webhook signature check, idempotency on `stripe_session_id`, rollback on credit failure.
- **Cost awareness.** Every paid call carries `UsageMeta`. Prompt caching is designed per breakpoint. Payload caps (`CAPS`) and per-route rate limits exist.
- **CI on every PR**: `tsc --noEmit`, lint, vitest, `next build`.
- **Worker-budget engineering**: lazy Supabase/Anthropic clients and the Sentry-lite server reporter keep OpenTelemetry out of the bundle.
- **i18n (en/pt)** across prompts and challenges. The shared challenge library has a top-up agent endpoint.

## 3. Findings in detail

### 3.1 HIGH — `sessions` writable from the browser → ranking farming

`001_initial_schema.sql`:

```sql
create policy "Users can manage their own sessions"
  on public.sessions for all
  using (auth.uid() = user_id);
```

Migration 010 closed this hole for `profiles` but left `sessions` (and
`code_submissions`) open. Any logged-in user holds a Supabase session in the
browser and can call PostgREST directly:

1. `update sessions set points = null where id = <own session>`, then call the
   `completeSession` server action again. `completeSession` only checks
   `session.points === null`. `award_session_points` then finds no *other*
   scored session for that challenge and awards the points again. Repeat for
   unlimited `total_points` and league points.
2. `insert` sessions with `status = 'completed'` and back-dated `started_at`.
   `calcStreak` reads exactly those rows, so the user gets fake streaks and
   `award_streak_hints` pays out free hints.
3. `update sessions set independence = …` decides who appears in "how others
   solved it" (`independence > 0`).

**Fix:** migration that replaces the policy with `for select` only, plus
`revoke insert, update, delete on sessions from authenticated` (all writes
already go through server actions with the service role). Do the same for
`code_submissions` and `hints_used`. Make `award_session_points` key off
"already awarded" with a timestamp the client cannot clear.

*Confirmed by reading the code only. Not exercised against production.*

### 3.2 HIGH — replay tampering via unowned `session_id`

`/api/review` and `/api/design-review` authenticate the caller, then:

```ts
await supabaseAdmin.from('code_submissions').insert({
  session_id: sessionId,   // from the request body, ownership never checked
  user_id: userId, code, review_response: review,
})
```

`/replay/[id]` is public by design (shared on social). It reads the **latest**
`code_submissions` row for that `session_id`, without a `user_id` filter. Anyone
with a replay link can replace the code and AI review the page shows, including
a misleading or offensive "review".

**Fix:** before any insert, load the session and require
`session.user_id === userId`. Filter the replay query by `user_id = session.user_id`.

### 3.3 MEDIUM — client controls the prompt context (hint economy bypass)

`/api/tutor` builds the system context from `body.title` / `body.briefing`.
It replays `body.messages` with roles taken from the client, so `assistant`
turns can be forged. A user can describe a different challenge, or forge prior
tutor turns, and get a full solution in `reply` mode. That mode is free (no
hint consumed) and is supposed to answer only with questions. `/api/solve`
also trusts `title` and `briefing`.

**Fix:** require `session_id` in every mode and load the challenge
(title, briefing, tests) server-side from the session. Accept only `user`
content from the client. Ideally, persist the transcript server-side and
replay it from there. Add an eval case for "forged assistant turn".

### 3.4 MEDIUM — cross-user hints

`consume_hints(p_user, p_session, …)` inserts `hints_used` for any
`p_session`. `award_session_points` blocks scoring when *any*
`hints_used.is_solve` row exists on the victim's sessions of that challenge,
and it never filters `h.user_id`. Spending 5 of your own hints on someone
else's session id zeroes their award. Session ids leak through replay links.

**Fix:** the same ownership check as in 3.2, inside `consume_hints`
(`perform 1 from sessions where id = p_session and user_id = p_user`), plus
`h.user_id = p_user` in the award query.

### 3.5 MEDIUM — no spend cap; confirm sign-up is closed

- `ai_usage` (026) is a ledger only. No per-user daily or monthly token or cost
  limit is enforced. The only brake is per-minute rate limiting: tutor 40/min,
  review 20/min, solve 10/min, generate 10/min. `rateLimit` **fails open** on
  DB errors.
- Access depends on the platform login. However, the Supabase anon key is
  public (`NEXT_PUBLIC_*`). If **email sign-up is enabled** in the Supabase
  project, anyone can create a user through `/auth/v1/signup` and use every AI
  route without a Borderless account. This could not be verified from the repo
  because there is no `supabase/config.toml`.

**Fix:** disable sign-ups in Supabase Auth and record it in the docs. Add a
monthly per-user cost cap computed from `ai_usage`, checked in `requireUser`
callers, as Hone's token cap does.

### 3.6 MEDIUM — test and build gates

- 8 test files, all pure domain or helper functions (`scoring`, `season`,
  `streak`, `independence`, `period`, `parse-json`, `usage`, runner worker).
- Nothing covers routes, server actions, RLS policies or the Stripe webhook,
  and there is no Playwright smoke. 3.1–3.4 are the kind of bug those tests catch.
- CI builds with `next build`. Production uses `opennextjs-cloudflare build`,
  which broke in July (PRs #2–#4) and again in August (stale `bun.lock` hotfix)
  without CI noticing.

**Fix:** add `npm run build:cloudflare` to CI. Add RLS tests against a local
Supabase (`supabase start`), route tests for ownership, and a Playwright smoke:
login → challenge → tutor → submit → replay.

### 3.7 MEDIUM — delivery and process

- No issue key in branches or commits. GitHub issues are disabled. There is no
  Linear project activity.
- History lives in two orgs: PRs #16 and #17 merged from
  `ProgramadoresSemPatria`, PRs #1–#5 in `BorderlessCodingHub`. Four merged
  branches were never deleted.
- The deploy path (Cloudflare Workers Builds? manual `npm run deploy`?) and its
  required env vars (`AUTH_API_URL`, `NEXT_PUBLIC_SITE_URL`, `STRIPE_*`,
  `AGENT_SECRET`, `SENTRY_*`, `POSTHOG_*`) are not written down anywhere.
  `.dev.vars.example` lists only some of them.
- Idle since 2026-08-29. Nobody currently owns production.

### 3.8 MEDIUM — documentation drift

- The README describes **Excalidraw** (removed; the canvas is `@xyflow/react`)
  and a **Vercel** deploy. `vercel.json` and `@vercel/analytics` are leftovers.
- No `.specs/`, `ROADMAP`, `STATE` or decision log. Decisions live only in
  migration comments, which are good but hard to find.
- `CLAUDE.md` is `@AGENTS.md`, and that file holds only the Next.js-16 warning.
  It has no product, stack, command or rule context for agent sessions.
- `.github/workflows/claude.yml` pins `claude-opus-4-7`.

### 3.9 LOW — cold start

The `keep-warm` workflow documents a 5–8 s cold start caused by the server
bundle size, and pings 3 pages every 10 min. It works, but it costs GitHub
Actions minutes and hides the root cause. Measure the bundle
(`.open-next/server-functions`), then move heavy server-only dependencies
(Stripe, Anthropic SDK) behind dynamic imports or split routes.

### 3.10 LOW — hygiene

- `library-topup`: `x-agent-secret !== secret` → use `timingSafeEqual`.
- `supabase/.temp/` committed (project ref, pooler host). Add it to `.gitignore`.
- Sign-in rate limit is keyed by email only. Add a per-IP key.
  `clientIp` already exists but is unused.
- Hard-coded Portuguese error strings in routes, while the UI is bilingual.

**authorization at the data layer** and its **operating system** (tracker,
specs, docs, ownership) lag. One migration closes most of the security gap.
Copying Career Forge's workflow closes the rest.

## 5. Quarter focus (decided 2026-11-09, target 2026-12-31)

socratic.dev becomes **System Design only**, with progression on the
Borderless tiers: Tier 0 (BASE), I, II, III. A badge reads "System Design:
ready for Tier II". It does not mean a PSP promotion. Tier IV left the
hierarchy in v3.1.

| Tier | What the interview asks | Example challenges |
|---|---|---|
| 0 | Fundamentals: client, API, database, cache | URL shortener |
| I | First global contract: a service that scales on its own | Rate limiter, file upload |
| II | Senior: consistency, failures, queues | Chat, news feed |
| III | Staff: multi-region, cost, org-level trade-offs | Payments, global search |

The code track is hidden first, then removed. Tier progression replaces
levels, points, leagues and streaks.
